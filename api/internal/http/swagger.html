WallAce · API Explorer

Explore device settings, heartbeats, and motion events.

Download OpenAPI

1. Authorize requests

Click Authorize below and enter your API_TOKEN without Bearer. Local Compose uses dev-token unless changed in .env. No account or password is needed.

2. Choose a device

Use the ESP32 factory MAC address as device_id. To simulate a device, send a heartbeat with the example MAC, then list devices. An empty list means no devices have contacted the API.

3. Execute a request

Expand an operation, fill its parameters, then click Execute. A 401 means the token is missing or incorrect. Health checks are public. Requests use the current host.

WebSocket guide · live detection stream

API → connected dashboards

Connect to /ws/dashboard. The ESP32 sends detections over HTTP; the API saves each event in PostgreSQL and broadcasts it to every connected dashboard. The stream is currently public. Use device_id to identify each sensor.

Configuration changes use HTTP PUT, and the ESP32 polls them with GET every 3–5 seconds. Heartbeats and online status also use HTTP. Sending client messages on this socket does not execute API commands.

Observe events in your browser console

Run this on the dashboard or this docs page. Then authorize and execute POST /api/devices/{device_id}/detections below to generate an event in the running database. HTTP Execute buttons do not open a WebSocket themselves. 

const protocol = window.location.protocol === 'https:' ? 'wss:' : 'ws:';
const socket = new WebSocket(`${protocol}//${window.location.host}/ws/dashboard`);
socket.addEventListener('message', (event) => console.log(JSON.parse(event.data)));
socket.addEventListener('close', () => console.log('WebSocket disconnected'));

A detection message looks like this; ts is Unix seconds: 

{
  "type": "detection",
  "device_id": "A4:CF:12:34:56:78",
  "ts": 1732300000
}

Run socket.close() when finished. Delivery has no acknowledgements or replay; disconnected or slow clients can miss events. Recover persisted history with GET /api/devices/{device_id}/detections, using limit and offset. The current dashboard does not reconnect automatically: reload it after a disconnection and open the device history. The full message contract is in x-websockets in the downloadable OpenAPI file.
